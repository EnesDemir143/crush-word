# Phase 01.1 Data Architecture

Bu dokuman, gameplay implementation baslamadan once kalici veri sinirini, config kapsamini, SQLite secimini ve hedef klasor yapisini dondurur.

## Canonical Package Choices

### `shared_preferences`

`shared_preferences`, yalnizca hafif key-value state icin kullanilacaktir.

Canonical sahiplik:
- `profile.username`
- ileride gerekirse hafif UI tercihleri

`shared_preferences` icine alinmayacak state:
- aktif oyun gridi
- skor gecmisi
- coin bakiyesi
- joker envanteri
- app background/resume checkpoint state

### `sqflite`

Structured local data icin tek canonical SQLite paketi `sqflite` olarak secildi.

Supporting packages:
- `path`

Secilmeyen aday:
- `drift`
  Sebep: Bu repo icin gereksiz abstraction ve operational weight ekliyor.

## Database Contract

- Database filename: `word_crush.db`
- Database owner: tek `AppDatabase` giris noktasi
- Migration strategy: integer schema version + forward-only migration listesi
- Persistence style: repository -> `lib/src/core/persistence/sqlite/` adapter/mapping katmani -> `sqflite`

Bu projede ayni anda yalnizca tek aktif oyun oturumu desteklenecegi icin `session_checkpoint` tablosu singleton active-session mantigiyla tasarlanacaktir; ayrica coklu session history sistemi kurulmayacaktir.

## Config Boundary

Runtime config dosyasi:
- `assets/config/game_rules.json`

Config runtime kodu:
- `lib/src/core/config/`

Format karari:
- `JSON` canonical config formatidir.
- `YAML` kullanilmayacaktir.

### `config-driven` alanlar

`config-driven` tutulacak sabitler:
- harf puanlari
- joker fiyatlari
- zorluk -> grid boyutu / hamle sayisi eslesmeleri
- Turkce harf frekans agirliklari
- power threshold degerleri
- baslangic coin miktari

### `code-driven` alanlar

`code-driven` tutulacak davranislar:
- combo `subsequence` algoritmasi
- non-overlapping kelime sayisi hesabi
- grid solvability / fallback algoritmasi
- power tile board etkileri
- SQLite persistence / migration akisi

Kural: `game_rules.json` yalnizca ayarlanabilir sabitleri tasir; davranis semantigi config dosyasina tasinmaz.

## Minimum SQLite Schema

### `game_results`

Amac: tamamlanmis veya onayli terk edilmis oyun sonucunu Phase 5 skor gecmisi icin saklamak.

Minimum alanlar:
- `id` TEXT PRIMARY KEY
- `completed_at` TEXT
- `difficulty` TEXT
- `grid_size` INTEGER
- `starting_moves` INTEGER
- `score` INTEGER
- `words_found_count` INTEGER
- `longest_word` TEXT
- `duration_seconds` INTEGER

Not:
- newest-first sorgu `completed_at DESC` ile okunur.
- aggregate metrikler Phase 5'te bu tablo uzerinden hesaplanir; ayri summary tablosu acilmaz.

### `player_wallet`

Amac: oyuncunun coin bakiyesini tek canonical source olarak saklamak.

Minimum alanlar:
- `wallet_id` TEXT PRIMARY KEY
- `coin_balance` INTEGER
- `updated_at` TEXT

Karar:
- Bu tablo tek satirli singleton model kullanir (`wallet_id = player`).
- Coin state, `session_checkpoint` icinde duplicate edilmez.

### `joker_inventory`

Amac: satin alinmis ve kullanilabilir joker adetlerini joker tipine gore saklamak.

Minimum alanlar:
- `joker_type` TEXT PRIMARY KEY
- `owned_count` INTEGER
- `updated_at` TEXT

Karar:
- Katalog/fiyat bilgisi bu tabloda tutulmaz; o bilgi `game_rules.json` / canonical catalog tarafinda kalir.
- Bu tablo yalnizca sahiplik/adet bilgisini tasir.

### `session_checkpoint`

Amac: app background/resume sonrasi aktif oyunu geri yukleyebilmek.

Minimum alanlar:
- `checkpoint_id` TEXT PRIMARY KEY
- `game_config_json` TEXT
- `board_json` TEXT
- `remaining_moves` INTEGER
- `elapsed_seconds` INTEGER
- `current_score` INTEGER
- `words_found_count` INTEGER
- `longest_word` TEXT
- `selected_path_json` TEXT
- `power_tiles_json` TEXT
- `updated_at` TEXT

Karar:
- Bu tablo tek satirli singleton active-session modeli kullanir (`checkpoint_id = active_session`).
- Resume akisi grid, remaining moves ve elapsed time bilgisini buradan alir.
- Coin state restore edilirken `player_wallet`, joker restore edilirken `joker_inventory` birlikte okunur.
- `session_checkpoint` coin veya fiyat gibi ekonomi state'ini duplicate etmez.

## What Is Intentionally Not A Separate Table

Asagidaki alanlar icin ayri SQLite tablo acilmayacaktir:
- profil / kullanici adi
  Sebep: `shared_preferences` yeterli
- harf puan tablosu
  Sebep: `assets/config/game_rules.json`
- joker fiyatlari ve aciklama katalogu
  Sebep: `assets/config/game_rules.json` veya ayni canonical config loader
- combo gecmisi
  Sebep: history ekraninin ihtiyaci degil; runtime hesap yeterli
- tek tek board hucreleri icin normalize `board_cells` tablosu
  Sebep: aktif oyun snapshot'i icin `board_json` daha dusuk karmasiklik saglar
- ayri `power_tiles` tablosu
  Sebep: active session snapshot'inda `power_tiles_json` yeterli
- ayri aggregate/summary tablosu
  Sebep: skor verisi kucuk; `game_results` uzerinden read-time hesap yeterli

## Restore Contract

Background/resume restore icin minimum okunacak kaynaklar:
1. `shared_preferences` -> profil ve hafif tercihler
2. `session_checkpoint` -> grid, `remaining_moves`, `elapsed_seconds`, score ve aktif board metadata
3. `player_wallet` -> coin bakiyesi
4. `joker_inventory` -> sahip olunan joker adetleri

Bu kontrat sayesinde app resume sonrasinda su veriler kaybolmadan geri yuklenebilir:
- grid
- remaining moves
- elapsed time
- current score
- power tile metadata
- coin state
- joker inventory state

- Structured local store = `sqflite`
- Lightweight preferences = `shared_preferences`
- Database file = `word_crush.db`
- Runtime config format = `JSON`
- Config file = `assets/config/game_rules.json`
- Behavior ownership = `config-driven constants` + `code-driven logic`
